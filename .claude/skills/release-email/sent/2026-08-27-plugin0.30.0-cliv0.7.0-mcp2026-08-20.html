bluestep-tools plugin
0.30.0 Six platform-reference fixes from your feedback. The formula rule demanding a /// <reference> line on line 1 is gone (no reference line is needed — the build wires the types in), and the merge-report docs no longer list a mergeTagResult() method that isn't there. New gotcha pages: entry().viewUrl() returns a javascript: call rather than a URL, some option lists truncate BSJS display names by one character, and option-list export values are readable via GraphQL.
0.29.5 B.ai reference corrected. The docs now carry the platform's full stopReason vocabulary, and state that configure() and usageReporting() are superuser-only — a script can't read or set its own spend budget.
0.29.4 Merge-report URLs on a record. viewUrl() returns a record-less URL (that's the "No Record Selected" page, not a permissions bug); the reference now documents the record-scoped _id/_id2 URL shape that does open a report on a record.
0.29.3 Document-library folder keys gotcha. subFolders() keys each child by its name plus a trailing slash, so the obvious lookup silently returns undefined. Now documented, with the fix.
0.29.0 A plain push does not deploy. The scaffolded project rules no longer imply it does: a plain b6p push uploads draft source only and never changes the live version. If a change doesn't show up on the page, check the push mode first — before blaming caches.
0.28.0 The b6p skills caught up with CLI 0.6.x. Auth is a single access token now (b6p auth set — everyone gets re-prompted once on upgrade), pulls keep your locally-edited files and say which ones were kept, push results are read from the exit code, and the legacy draft/info/ folder is documented as deprecated — read it when present, never expect it.
To update, run /plugin marketplace update
b6p CLI
v0.7.0 Snapshot pushes now type-check for real. The pre-push check finally loads your component's declaration files, so the wall of false Cannot find name errors is gone — what remains is real, and b6p push --snapshot now fails the shell on genuine type errors (the platform runs the emitted JS unchecked, so this push is your only type gate). Failed pushes no longer exit 0, prompts fail loudly instead of hanging, and pulls keep locally-edited files. If you're on the v0.4.0 binary, every snapshot push spams bogus diagnostics — update.
To update, run npm i -g @bluestep-systems/b6p-cli — standalone binaries are on the release page.

Heads-up: the updated CLI will ask you to sign in again (b6p auth set). If you don't have an access token, reach out to Steve and he'll get you one.
BlueStep gateway MCP
Aug 20 Fields can carry their identifier from the start. The field and batch_fields tools take formulaId (the admin-UI Field Identifier) on CREATE and UPDATE, so new fields land in the generated declarations with a proper property key — and a field created without one can be repaired afterwards.
Aug 20 Signature fields get the Display Credential checkbox. The field tools accept displayCredential, and it defaults on at create time when the org has credential fields — same gate as the UI.
Aug 20 The form tools' userUpdateable flag is honest now. It's the platform's "Show in My Account" checkbox, not entry editability — the schema says so, and its CREATE default flipped to false to match the platform.
Aug 20 Three fixes. A form's singleEntry setting now persists on create, create_script reports a privilege problem up front instead of after appearing to create something, and lookup_script_by_name finds BSJS endpoints.
Nothing to install — these changes are already live on the gateway.
