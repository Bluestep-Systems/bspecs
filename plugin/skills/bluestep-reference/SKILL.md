# BlueStep Instruction Index

This is the navigation hub for the on-demand BlueStep rules. It is read when needed, not auto-loaded — Tier-1 critical rules stay in `CLAUDE.md`, and the Tier-2 overviews (`b6p-platform.md`, `bsjs-development.md`) cover the high-frequency platform and BsJs material. ## conventions/ — build, deploy, and workflow directives

- [conventions/date-format.md](conventions/date-format.md) — `addSearch` needs `MM/DD/YYYY` for date fields; `YYYY/MM/DD` passes validation but silently fails to filter, and raw Java `LocalDate` objects also fail. Load when filtering a query by a date field.
- [conventions/deploy-lib-workflow.md](conventions/deploy-lib-workflow.md) — deploy an off-platform Vite/Preact SPA merge report with deploy-lib: install from git, the `package.json` `config` block (`deployUrl` is camelCase; `deploypathsuffix`/`builddir` lowercase), the `deploy` script, `npm run deploy -- --build --clean` (draft+snapshot upload), auth resolution (`--token-file` → `BLUESTEP_TOKEN` → `.env-local` → interactive, Bearer), Node 20+. Load when wiring or running a deploy-lib deploy for a `static/` SPA bundle.
- [conventions/endpoint-approach.md](conventions/endpoint-approach.md) — research-first: gather API docs, read type declarations, and study existing examples before writing an endpoint. Load when starting a new endpoint.
- [conventions/formula-patterns.md](conventions/formula-patterns.md) — correct BSJS formula patterns: form access, field reads/writes, HTTP, error handling, `B.*` utilities, DocumentLinkField. Load when writing a Formula or Post-Save script.
- [conventions/mcp-platform-authoring.md](conventions/mcp-platform-authoring.md) — the single shared procedure for a `[PLATFORM]` authoring/wiring op via the bundled platform-gateway MCP: connection-check (gateway tools live? fix = enable the `bluestep-tools` plugin + set `$B6PT_TOKEN` + restart) → resolve the target org to a U-number (user-supplied → `available_tenants` map → unlisted ≠ unreachable) → map op to an inner tool (optional `op:` hint), `list_org_tools` for schemas → approval echo of the concrete `invoke_org_tool` call (org + inner tool + args) → execute via `invoke_org_tool` → declaration read-back (`invoke_org_tool(tool:get_script_declarations)`) → idempotency detect-and-skip → destructive-tool discipline, plus the supported tool set. `/spec-execute`, `/quick-task`, and free conversation all follow it. Load when about to add an import (query/form/field) or create a form/field/option-list/view/record-type via the gateway MCP.
- [conventions/no-global-dollar.md](conventions/no-global-dollar.md) — never define a global `$` in MergeReport scripts; pages use jQuery and you will silently break Save and all page interactivity. Load when adding client JS to a MergeReport.
- [conventions/separate-files.md](conventions/separate-files.md) — don't pile CSS/HTML/JS into `app.ts`; use the `styles.css`/`index.html`/`script.ts` files the pulled folder already has. Load when structuring MergeReport files.
- [conventions/single-script.md](conventions/single-script.md) — the server-side build compiles only root `static/script.ts` to `.build/script.js`; subdirectory `.ts` files are NOT compiled. Load when splitting client scripts into multiple files.
- [conventions/top-level-const-tdz.md](conventions/top-level-const-tdz.md) — endpoint/MergeReport scripts run top-down; declare every `const`/`let` above the entry `try` block or they are in TDZ when the handler fires. Load when ordering declarations in an endpoint or MergeReport.
- [conventions/ts-in-template-literal.md](conventions/ts-in-template-literal.md) — the inline `<script>` inside a `B.out` template literal must be plain JS; any TypeScript syntax ships verbatim to the browser and breaks parsing. Load when emitting client JS through a `B.out` string.

## gotchas/ — sharp edges

- [gotchas/b-exports-proxy-map.md](gotchas/b-exports-proxy-map.md) — `B.exports` is a Java-side proxy map (`ProxyJavaMap`), not a plain JS object; a value read back is a Java host object, so the accumulate pattern `B.exports.k = B.exports.k || []; B.exports.k.push(v)` type-checks locally but throws `Unknown identifier: push` at runtime; store structures as JSON strings (primitives round-trip). Load when passing data through `B.exports` between formulas/commit boundaries, especially arrays/objects.
- [gotchas/common-gotchas.md](gotchas/common-gotchas.md) — anti-pattern roundup: Java optionals vs JS null checks, Java collections vs JS arrays, server/client separation, MergeReport HTML structure, SweetAlert2 v8 vs v11, ES feature limits, strict mode, query access, script-timing race. Load when debugging a silent failure or before writing new component code.
- [gotchas/fetched-resource-code.md](gotchas/fetched-resource-code.md) — `FetchedResource.code()` returns `0` on success, not the upstream HTTP status; only `code >= 400` reliably indicates failure. Load when checking the result of a fetched resource.
- [gotchas/relate-query-over-mefr.md](gotchas/relate-query-over-mefr.md) — reading multi-entry form data via a `view`-tool Relate query has four traps: `maxRows: 0` means literally zero rows (and is the default — use `-1`), `recordTypes` must be the record's BASE type (not the form's category), `list_views(formId:)` can't prove absence (omits MEFRs), and `relateQuery` can't execute an EntityList — use a `List` view for data reads (`create_mefr`'s EntityList is for script imports). Load when creating or querying a Relate view over a multi-entry form via MCP.
- [gotchas/vite-merge-report-gotchas.md](gotchas/vite-merge-report-gotchas.md) — sharp edges of the off-platform Vite/Preact SPA merge report: `base: './'` is mandatory (Vite defaults to `/`, assets 404 on-platform → blank render), `<head>` stripped but body `<script>`/`<link>`/mount-`<div>` survive, mount id must match, Node 20+ (`crypto is not defined` on 18), deploy-lib `deployUrl` camelCase casing, site CSS / `Swal` absent in local dev. Load when a Vite merge report renders blank/unstyled or a deploy fails.
